## What this repo is

`@infogata/videogata-plugin-typings` — the ambient TypeScript type declarations for [VideoGata](https://github.com/InfoGata/videogata) plugins. It ships **no runtime code**: `index.js` is intentionally empty and `main` in `package.json` is `""`. The entire package is `index.d.ts`.

Plugin authors consume it either via `"types": ["@infogata/videogata-plugin-typings"]` in their tsconfig or `import "@infogata/videogata-plugin-typings";`.

## Commands

```sh
npm test          # runs `tsc` (noEmit, strict) — the only check; there is no test suite

cd docs
npm start         # dev server; regenerates the TypeDoc API pages on start
npm run build     # production build of the docs site
npm run typecheck # tsc for the docs site
```

## Architecture

### `index.d.ts` — one global `declare global` block

Everything is declared inside a single `declare global { ... }` with a trailing `export {}` to make the file a module. This is what makes `application`, `Video`, `Playlist`, etc. available to plugin code with no imports.

The `Application` interface has two distinct halves, and the distinction matters when adding members:

- **Host methods** (non-optional): things the plugin *calls* on VideoGata — `networkRequest`, `postUiMessage`, `getPlaylists`, `endVideo`, `createNotification`, …
- **Plugin callbacks** (`on*`, almost all optional): things the plugin *implements* and VideoGata calls — `onSearchVideos`, `onGetVideo`, `onGetChannelVideos`, …

Callbacks are optional because their presence is what enables a feature in the host UI; the doc comment on each one names the route it powers (e.g. `/plugins/:pluginId/videos/:apiId`). Preserve that convention — the TSDoc comments are the published API documentation, not incidental commentary.

Paginated results follow a consistent shape: a request carries `pageInfo`/`filterInfo`, and results extend `SearchResult` (`SearchVideoResult`, `SearchPlaylistResult`, `SearchChannelResult`), with `PlaylistVideosResult`/`ChannelVideosResult` extending `SearchVideoResult` to add the parent entity.

`Manifest` mirrors the plugin's `manifest.json`; keep it in sync with `docs/docs/plugins/plugin-manifest.md`.

### `docs/` — Docusaurus site (separate npm project)

Deployed to GitHub Pages at `infogata.github.io/videogata-plugin-typings/`. It is excluded from the published npm package via `.npmignore`.

The API reference under `docs/docs/plugins/api/` is **generated by `docusaurus-plugin-typedoc` from `../index.d.ts`** and is **committed to git**. Running `npm start` or `npm run build` in `docs/` rewrites those files. After changing `index.d.ts`, regenerate and commit the resulting markdown so the docs match the types. Hand-written pages are `docs/docs/intro.md`, `plugins/installation.md`, and `plugins/plugin-manifest.md`.

## Releasing

Version bumps are done locally; CI publishes on the tag (`.github/workflows/publish.yml`):

```sh
npm version <patch|minor|major>
git push --follow-tags
```

The workflow runs `npm test`, verifies the `vX.Y.Z` tag matches `package.json`, publishes via npm OIDC trusted publishing (no `NPM_TOKEN`), and cuts a GitHub Release. A tag whose version doesn't match `package.json` fails the build.
